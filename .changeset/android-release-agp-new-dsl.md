Android release build fixed (#466): the release AAB and emulator jobs failed evaluating the `:expo` project because expo-constants' Gradle script still reads the legacy `libraryVariants` API that AGP 9's new DSL removed (a regression from the Expo autolinking wiring in #464). The app now sets AGP's documented `android.newDsl=false` compatibility opt-out in `gradle.properties`, restoring the previous DSL so the release build configures cleanly. With configuration fixed, dependency resolution then exposed a second failure: `settings.gradle`'s `RepositoriesMode.PREFER_SETTINGS` silently discards the per-package `local-maven-repo` directories expo-modules-autolinking registers at project level for its AAR-published modules (expo.modules.asset, host.exp.exponent:expo.modules.*), so those artifacts could not be found in google()/mavenCentral()/jitpack. The settings-level repositories now mirror every `local-maven-repo` directory shipped under node_modules — scanning both the app and workspace-root node_modules trees, including packages nested inside other packages' node_modules, because npm hoisting makes any one package's location unstable across installs. With resolution fixed, the fixture build then failed `:expo:checkReleaseAarMetadata`: Expo SDK 58's AAR-published modules declare `minCompileSdk 37` in their AAR metadata while the project compiled against Android 36. The project now compiles against Android 37 (`compileSdkVersion 37`, build-tools 37.0.0, and the CI Android setup installs the android-37 platform); `targetSdkVersion` stays 36, so runtime behavior is unchanged. No user-facing behavior changes.
